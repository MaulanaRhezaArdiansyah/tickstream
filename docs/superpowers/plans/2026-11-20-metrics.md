# /metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Owner-only `GET /metrics` in Prometheus text format covering the Finnhub feed, Finnhub REST quota, caches, WebSocket clients and HTTP requests.

**Architecture:** One new module `server/src/metrics.rs` owns every metric name and exposes small recording functions; the rest of the server calls those functions and never names a metric itself. `main` installs the Prometheus recorder globally and puts its `PrometheusHandle` in `AppState`; the `/metrics` handler renders it behind the existing `Admin` extractor. Tests swap in a thread-local recorder (`metrics::set_default_local_recorder`), which works because `#[tokio::test]` and `#[sqlx::test]` run on a current-thread runtime.

**Tech Stack:** Rust, axum 0.8, `metrics` 0.24, `metrics-exporter-prometheus` 0.18 (`default-features = false`, no HTTP listener), `metrics-util` 0.20 (dev only, `DebuggingRecorder`).

**Spec:** `docs/superpowers/specs/2026-11-20-metrics-design.md`

## Global Constraints

- Every metric name starts with `tickstream_`; names, kinds and labels exactly as the spec's table.
- No symbol, IP, token or API key in any label. `route` is the axum route pattern (`MatchedPath`); anything without one is `other`.
- `/metrics` answers 401 without the right `Authorization: Bearer <ADMIN_TOKEN>`, and 401 when no token is configured (use `crate::auth::Admin`).
- Response content type `text/plain; version=0.0.4`.
- `/health`, nginx, Docker and `web/` are unchanged. No new Finnhub calls.
- Never run the server binary locally (it opens a second Finnhub WebSocket on the prod key). Tests only.
- Checks: `cargo fmt`, `SQLX_OFFLINE=true cargo clippy -q --all-targets --locked -- -D warnings`, `cargo test` (needs the dev Postgres from `docker compose up -d`).
- Commit trailers as in previous commits.

## Review Focus

1. `ADMIN_TOKEN` unset → `/metrics` must be 401, not an open page (Task 1 test).
2. A path with a symbol in it is labelled by its pattern, and a path that matches no route is `other`, so cardinality stays bounded (Task 2 test).
3. A WebSocket client that disconnects must bring `tickstream_ws_clients` back down, whichever way the task ends (Task 5 test; guard decrements on `Drop`).
4. A cache lookup whose loader fails counts as a miss, never a hit (Task 3 test).
5. The duration metric renders as a real histogram (`_bucket` lines), not the exporter's default summary (Task 1 test).

### Task 3: cache hit and miss

**Files:** Modify `server/src/metrics.rs`, `server/src/market/cache.rs` (+ its tests).

**Interfaces:**
- Produces `pub fn cache_lookup(cache: &'static str, hit: bool)`: counter `tickstream_cache_requests_total{cache, result="hit"|"miss"}`.
- Cache names: `quote`, `profile`, `market_status`, `news`, `symbols`.
- Rule: **miss** when this call ran the `try_get_with` init future **or** the result is `Err`; otherwise **hit**. Detect "ran" with a flag set inside the init future (e.g. an `AtomicBool` captured by reference); one helper in `cache.rs` wraps all five methods so the rule lives in one place.
